# 视频内容提取（Video Content Extraction）

把一个视频变成三份交付物，全部保存在输出目录（默认在视频同目录下建 `<视频名>-extract/`）：

1. **`transcript.md`** — 主讲人转录文字稿，带时间戳，按语义分段
2. **`mindmap.md`** — 覆盖视频全部知识点的脑图（Mermaid mindmap）
3. **`notes.md`** — 对整个视频的详细结构化笔记

用户只要求其中一件时，仍然先完成转录（后两件都以它为原料），再只交付用户要的那件。

## 工作流程

### 第 0 步：环境准备

运行一次依赖检查/安装（幂等，已装则跳过）：

```bash
bash <skill目录>/scripts/setup.sh
```

安装内容：ffmpeg（apt）、faster-whisper（pip）、yt-dlp（pip，仅在输入是 URL 时需要）。

### 第 1 步：拿到视频文件

- **本地文件**：直接使用。先用 `ffprobe` 确认文件有效、有音轨。
- **URL**（YouTube / Bilibili 等）：`yt-dlp -f "bv*[height<=720]+ba/b" -o "<输出目录>/source.%(ext)s" <URL>`。只需要音频做转录时可用 `-f ba` 只下音频，更快。
- 拿不到视频（链接失效、地区限制、无网络策略）时，明确告知用户原因，不要凭标题猜测内容。

### 第 2 步：提取音频

```bash
python3 <skill目录>/scripts/extract_audio.py <视频文件> <输出目录>/audio.wav
```

脚本会输出视频时长、分辨率等元数据（JSON 到 stdout）。记下时长——它决定后面模型选择和分段策略。

### 第 3 步：语音转录

```bash
python3 <skill目录>/scripts/transcribe.py <输出目录>/audio.wav <输出目录> [--model MODEL] [--language LANG]
```

- 模型选择：默认 `small`（速度/质量平衡）。视频 < 10 分钟或机器较慢时用 `base`；用户明确要求高精度且时长可接受时用 `medium`。首次运行会下载模型，耐心等待。
- 语言：默认自动检测。已知语言时显式传 `--language zh` / `--language en`，可避免误检且更快。
- 产出：`segments.json`（原始分段+时间戳）和 `transcript_raw.md`（初稿）。
- 长视频（>30 分钟）转录耗时可能达到视频时长的 1/5 ~ 1/2，用后台方式运行并定期查看进度，不要干等。

### 第 4 步：整理转录稿 → `transcript.md`

读取 `transcript_raw.md`，整理成正式转录稿。这一步是编辑工作，由你（而非脚本）完成：

- 按语义合并过碎的分段（Whisper 常按停顿切句），每段开头保留一个时间戳 `[MM:SS]`（超过 1 小时用 `[H:MM:SS]`）
- 修正明显的同音字/专有名词错误（结合上下文判断，如"神经网络"被转成"神经网路"、人名/术语拼写）。没把握的不要改
- 去掉无意义的口头禅重复（"呃"、"就是说就是说"），但**不改写句子、不概括**——这是转录稿，忠实性优先
- 文件开头写元信息：视频标题（如可知）、时长、语言、转录模型
- 多人对话时尽力标注说话人（`**主讲人：**` / `**提问者：**`），无法区分则不标

### 第 5 步：知识点脑图 → `mindmap.md`

通读整理后的转录稿，提取**全部**知识点，组织成层级结构。写法规范见 `references/mindmap.md`（写脑图前先读它）。要点：

- 用 Mermaid `mindmap` 语法，根节点是视频主题
- 覆盖度优先：视频里讲到的每个概念、方法、例子、结论都应能在脑图上找到对应节点，宁多勿漏
- 层级反映知识结构（主题 → 分支 → 概念 → 细节），而不是时间顺序
- 节点用短语不用长句；同层节点粒度一致

### 第 6 步：详细笔记 → `notes.md`

结构模板见 `references/notes-template.md`（写笔记前先读它）。要点：

- 按视频的内容章节组织（不是机械地按每 N 分钟切），每节标注起始时间戳，方便回看定位
- "详细"的标准：读完笔记不看视频，应能复述出视频讲了什么、为什么、例子是什么。记录论证过程和例子，不只记结论
- 主讲人口头强调的内容（"这个很重要"、"考试会考"、重复讲的点）用 **加粗** 或引用块突出
- 结尾给出：核心要点清单、术语表（视频中出现的专业名词+视频内给出的解释）、金句/原话摘录（如有）

### 第 7 步：交付

- 三个文件都写入输出目录，向用户报告文件路径和各文件一句话说明
- 有文件发送工具（如 SendUserFile）时把三个文件发给用户；mindmap 优先渲染展示
- 报告转录质量提示：音质差、多人重叠、背景音乐等导致的低置信段落要向用户说明

## 常见情况处理

- **视频拿不到**（超过聊天附件 30MB 上限、URL 被网络策略屏蔽、需要登录）：把 `assets/local-transcriber.html` 发给用户。这是一个单文件网页工具，在用户自己的浏览器里用 transformers.js 跑 Whisper 完成本地转录（文件不上传、无大小限制），转录完成后用户点"复制提示词"把转录稿粘贴回来，你再据此完成脑图和笔记。
- **视频没有音轨/纯音乐无人声**：转录不适用。改用抽帧（`ffmpeg -i in.mp4 -vf "fps=1/30" frame_%03d.jpg`）读取画面文字/幻灯片来构建脑图和笔记，并告知用户转录稿无法提供。
- **幻灯片型讲座**：转录之外，可抽关键帧读取幻灯片内容补充笔记（尤其是公式、图表、代码），在笔记中标注"[幻灯片内容]"。
- **超长视频（>2 小时）**：转录照常（脚本流式处理不怕长），但整理阶段分块进行：先分块通读生成各块小结，再汇总成脑图和笔记，避免一次性处理超出上下文。
- **多语言混杂**：faster-whisper 自动检测为主要语言，夹杂的外语词通常能正确保留；不要强制指定语言。
- **用户只给了音频文件**：跳过第 1-2 步的视频部分，直接转录（脚本接受任何 ffmpeg 可读的音频格式）。

## 忠实性原则

转录稿必须忠实于原话；笔记和脑图必须来自视频实际内容。视频里没讲的知识，即使你知道相关背景，也不要混入笔记正文——确有必要补充时，放在明确标注的"📎 补充说明（非视频内容）"块中。不确定听清的内容标注 `(?)`，不要脑补。
